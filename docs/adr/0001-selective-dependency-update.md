# Selective dependency update, deferring breaking majors

We update dependencies selectively rather than bumping everything to latest: safe patch/minor bumps plus low-risk majors go in now (Qwik 1.17→1.20, qwik-react 0.5.0→0.5.8, typescript-eslint 6→8, prettier 2→3, plus assorted type/tooling patches), while React 19, TypeScript 7, ESLint 9+/flat-config, Tailwind 4, Vite 8, and the Vercel CLI major are deferred. This isn't just caution — several are outright blocked by peer dependencies right now: `@builder.io/qwik@1.20.0` and `@builder.io/qwik-react@0.5.8` both require `vite: '>=5 <8'`, `qwik-react` peer-requires `react: '^18'` (React 19 unsupported), and `@typescript-eslint/eslint-plugin@8` requires `typescript: '>=4.8.4 <6.1.0'` (TypeScript 7 is incompatible). ESLint 9+ and Tailwind 4 are deferred separately because each needs its own config-format migration (flat config, CSS-based config) that would obscure a routine version-bump diff. There's no CI or test suite in this repo, so verification is manual (build + dev server + spot-check), which further argues against bundling risky migrations with routine bumps.

## Considered Options

- **Bump everything to latest** — rejected: several jumps are hard-blocked by peer dependencies (above) and would require simultaneous config migrations (ESLint flat config, Tailwind v4) with no automated test coverage to catch breakage.
- **Safe bumps only** — rejected as too conservative: typescript-eslint, prettier, and qwik-react each carry a major-version jump but no structural migration cost, just possible lint-rule/format-diff noise — worth taking now.

## Consequences

- Follow-up work needed to unblock each deferred package: React 19 needs a qwik-react release that supports it; TypeScript 7 needs typescript-eslint to raise its upper bound (or dropping the typescript-eslint pin); ESLint 9+ and Tailwind 4 each need their own dedicated migration pass; Vite 8 is gated entirely on Qwik itself raising its peer range above `<8`.
- `engines.node` moves from `>=15.0.0` to `>=18.11.0`, the actual intersection of Qwik's (`>=16.8.0 <18.0.0 || >=18.11`) and Vite 5's (`^18.0.0 || >=20.0.0`) Node requirements.
- Three implementation-time surprises worth remembering if this ever gets revisited: `vite-tsconfig-paths` went ESM-only at `5.0.0`, which breaks this project's CJS-loaded `vite.config.ts` — it's pinned at `4.3.2` (latest version that still ships CJS), not the newer major, until the config files themselves move to ESM. `qwik-react@0.5.6+` dropped its classic-Node-resolution shim for the `./vite` subpath export, which is why `tsconfig.json`'s `moduleResolution` is `"bundler"` now instead of `"node"`. `undici` needed a `pnpm-workspace.yaml` `overrides` entry, not just a `devDependencies` version bump — qwik-city depends on it with an unconstrained `"*"` range, and pnpm's isolated resolution won't make a sibling devDependency govern that nested copy on its own; without the override, two undici majors end up installed side by side.
